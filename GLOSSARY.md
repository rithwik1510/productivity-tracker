# Glossary

**Tracked App**: an app the user has explicitly selected for tracking. Only Tracked Apps are ever recorded; time in any other app is not counted or stored at all (see ADR-0001).

**Category**: one of exactly two fixed buckets, **Productive** or **Entertainment**. Every Tracked App belongs to exactly one. The user decides; the app never infers a category from what an app is (Discord can be Productive for one user and Entertainment for another). Changing an app's or site's Category affects future time only; past time keeps the Category it had when recorded (see ADR-0005).

**Daily Goal**: a single target of Productive time per day (e.g. 6h), the same every day. Shown as a progress ring. Entertainment time has no goal. The app never notifies or interrupts; the ring is the only motivation (break nudges are deferred to v2).

**Day**: a tracking day runs from 4:00am to 4:00am local time, not midnight to midnight. Time logged at 1:30am belongs to the previous Day. Every daily total, the Daily Goal ring, and History use this boundary. Fixed at 4am for now; not a setting.

**Tracked Site**: a website (by domain, e.g. `youtube.com`) the user has selected for tracking, with its own Category. Same opt-in rule as Tracked Apps: browser time on a site that isn't a Tracked Site is not counted (see ADR-0001, ADR-0002).

A browser may also be a Tracked App. **A Tracked Site always overrides its browser**: on a Tracked Site the site's Category applies; on any other site the browser's Category applies; if the browser isn't a Tracked App, other sites aren't counted.

**Active / Away**: time only counts while the user is Active. Evidence of presence is keyboard/mouse input, or sound from the foreground app (videos, calls). The user becomes Away after a stretch with no evidence set in Settings ("Count as away after": 2, 5, 10 or 15 minutes, 5 by default), and the counted time is trimmed back to the last evidence (so a 40-minute video counts in full). Sound alone can extend Active for at most 2 hours without input; hitting that cap makes the user Away and trims back to the last *input* (so an unattended 2.5h video counts as nothing, by design: missing real time is safer than inventing it). Screen lock, display off, sleep, and session disconnect make the user Away immediately, also trimmed back to the last evidence (so idle minutes just before a lock don't count). Unlocking counts as input. Presence is one state for everything that counts: Waiting credit counts only while the user is Active, and every Away rule trims it exactly as it trims the foreground. A minimized app's sound is not evidence. Every Active second counts once, for at most one target (see Waiting credit), so Productive plus Entertainment time never exceeds Active wall-clock time.

**Waiting credit**: a Tracked App whose Category is Productive counts while it is minimized and the user is waiting on it, so an agent or a render left running still counts (see ADR-0007, which replaced ADR-0006's parallel credit). Settings → "Keep counting minimized apps" turns it on or off: off on a new install (an install from before the setting existed keeps it on). When off, the order below skips its second step. Each Active second goes to one target, in this order: a Productive foreground (app or site); else a minimized Productive app with clock left; else an Entertainment foreground; else nothing. So with VS Code in front, a minimized Claude earns nothing; with YouTube, an untracked app or the desktop in front, Claude gets the time. Rules:
- The clock: 30 minutes from the first tick the app is seen minimized and not in front, once the tracker has seen it not minimized (in front, or restored). So an app that was already minimized when the tracker started (at login, after a restart or Delete all) gets no clock until it is brought back and minimized again. It keeps running while Away and while another Productive app is in front, so it is a window since the minimize, not 30 minutes of earning. It resets when the app comes to the front, is restored, or no longer has a minimized window; several minimized windows count once. Closing the app, untracking it or making it Entertainment stops it.
- Several minimized apps with clock left: the one with the most left (the latest minimize) gets the second; a tie goes to the app tracked first.
- Apps only. A minimized browser never counts for its tabs; it counts as itself only if it is a Productive Tracked App. Entertainment and untracked apps never wait in.
- Minimized means minimized to the taskbar. A window that is merely behind others, on another monitor or on another virtual desktop counts nothing, and neither does an app that hides to the tray when minimized (its window becomes hidden, not minimized).
- The Day view shows it inside an item's time ("incl. 18m waiting"); totals, History and the goal ring include it.

**Pause**: the user can stop tracking for 15 minutes, 1 hour or until tomorrow (the next Day boundary, 4am), from the tray only. While paused nothing counts, as if Away: pausing ends the open interval where a shutdown would (the last tick, trimmed back to the last evidence). The pause is stored, so a restart keeps it, and it ends on its own; Resume (tray, or the Day view's status line) ends it early. Presence is still followed while paused, so time counts again only if the user is there when it ends.

**App Identity**: how the tracker recognises the same app over time. If the process has package identity (Store/MSIX apps, whether UWP or packaged Win32 like Store Spotify or Windows Terminal), it is identified by its AUMID. Otherwise by exe file name, case-insensitive (`discord.exe`), so updates that move the install folder don't split history. The app picker must produce the same key the tracker does. See ADR-0003.

**Private windows** (Incognito, InPrivate, Private Browsing) are never tracked: neither Tracked Sites nor the browser's own Category count while one is in front. A browser window whose privacy the tracker hasn't been able to read yet (Chrome, Edge, Brave and the other browsers read through UI Automation, while that read fails or times out) counts as private until it is read: missing a normal window's time is safer than recording a private one.
